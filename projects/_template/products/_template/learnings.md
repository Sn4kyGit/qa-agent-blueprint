# Learnings — <KEY>/<PRODUCT>

Product-scoped learnings. `../../learnings.md` (project-wide) still applies to this
product — read both, they are never merged into one view.

Put an entry here when it is true for **this product only**. If it turns out to hold
for a sibling product too, `/retro-learn` moves it up to the project file; if it
holds for another JIRA project, it belongs in `memory/learnings/`. When in doubt,
keep it here: a too-narrow learning costs one repeated surprise next door and
corrects itself, a too-broad one silently misleads every product.

## Format rules

- Newest entries **on top**.
- Each entry: dated, 1–3 sentences, **Problem → Cause → Solution**.
- Entries seen again get their `seen:` counter bumped + date appended — no
  duplicate entries. Note which product each sighting came from
  (`seen: 2 — STOREFRONT, ADMIN`): two *different* products is the signal to
  promote this up to the project's `learnings.md`.
- Delete entries that no longer hold. Outdated learnings mislead.

## Entry template

```
### YYYY-MM-DD — <short title> (seen: 1)
- Problem: <what happened>
- Cause: <why>
- Solution: <what works now / what to do instead>
```
